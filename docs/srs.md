## 0. Конвенції документа

- Модальне дієслово «повинна / повинен / повинні» означає обов’язкову вимогу. Необов’язкові вимоги в документі відсутні.
- Ідентифікатори: `SRS-FUN-NN` (функціональні), `SRS-NFR-<КАТЕГОРІЯ>-NN` (нефункціональні), `SRS-IF-NN` (зовнішні інтерфейси). Ідентифікатори незмінні; видалена вимога не перевикористовується.
- Колонка «Походження»: `ЛР4` — перенесено з ЛР №4; `АУД` — додано або змінено за результатами ШІ-аудиту.
- Колонка «Статус значення» (NFR): `Виміряно` — значення підтверджено вимірюванням прототипу; `Ціль` — значення задано як ціль, підлягає підтвердженню в Розділі 3.
- Референсна конфігурація (РК): 2 ядра CPU, 8 ГБ RAM, Python 3.13, NumPy 2.5, Ubuntu 24.04 LTS.
- Позначення вихідних величин (QoI): дальність *R*, час польоту *T*, максимальна висота *H*, точка падіння (*x*, *z*). Позначення моделей: **M1** — вакуумна аналітична; **M2** — квадратичний опір зі сталою густиною; **M3** — розширена (ISA, C_d(M), вітер).
- Еталонний набір джерел невизначеності *d = 8*: початкова швидкість, кут піднесення, азимут, маса, коефіцієнт C_d, діаметр, складові вітру *w_x* та *w_z*.

## 1. System Context (Контекст системи)

### 1.1 Призначення та межі (Scope)

Система повинна забезпечувати кількісне оцінювання невизначеності результатів моделювання руху абстрактного навчального тіла в атмосфері: поширення невизначеності вхідних величин методом Монте-Карло (JCGM 101:2008), порівняння з лінеаризованим законом поширення невизначеностей (JCGM 100:2008, GUM) та аналіз внеску кожного джерела (глобальний аналіз чутливості). Система розгортається на одній робочій станції у двох формах: desktop-застосунок (GUI) та headless CLI (Docker-образ для CI/CD).

### 1.2 Поза межами системи (Out of Scope)

- бази даних реальних зразків озброєння;
- розрахунок поправок наведення;
- оцінка ураження цілей;
- мережевий (клієнт-серверний) режим, хмарне та розподілене виконання на кількох вузлах;
- обробка персональних даних.

### 1.5 Обмеження та припущення

- Обчислення виконуються на одній робочій станції; кластерне виконання не передбачено.
- Система не відкриває мережевих портів і не ініціює мережевих з’єднань під час роботи ([SRS-NFR-SEC-05](#srs-nfr-sec-05)).
- Арифметика — IEEE 754 binary64 (float64); похибка чисельного інтегрування повинна бути на порядок меншою за оцінювану невизначеність.
- Бітова відтворюваність гарантується в межах одного середовища (ОС, версії Python і NumPy); версії середовища зберігаються разом з експериментом ([SRS-FUN-46](#srs-fun-46)).
- Набір корисних вихідних величин і значення за замовчуванням, не зазначені у вимогах, визначаються в Розділі 3 і не змінюють вимоги.

## 5. Glossary (Глосарій)

| Термін | Визначення |
| --- | --- |
| Метод Монте-Карло (MC) | Чисельний метод поширення розподілів за JCGM 101: вхідні величини семплюються з їхніх розподілів, модель обчислюється для кожного семпла, вихідна вибірка апроксимує розподіл вихідної величини. |
| GUM (JCGM 100:2008) | Guide to the Expression of Uncertainty in Measurement; закон поширення невизначеностей ґрунтується на лінеаризації моделі першого порядку та коефіцієнтах чутливості. |
| Інтервал охоплення (coverage interval) | Інтервал значень вихідної величини із заданою ймовірністю охоплення; за JCGM 101 — найкоротший з інтервалів, що мають цю ймовірність. |
| SeedSequence | Механізм NumPy породження незалежних потоків випадкових чисел із кореневого seed методом `spawn`; використовується замість схеми «root seed + номер процесу», яку документація NumPy позначає як небезпечну. |
| Індекси Соболя | Дисперсійні міри чутливості: індекс першого порядку — частка дисперсії виходу, зумовлена одним джерелом; індекс повного порядку включає взаємодії з іншими джерелами. |
| Гауссова копула | Спосіб задання залежності між величинами з довільними маргінальними розподілами: корельовані нормальні величини (через Cholesky-розклад) перетворюються у рівномірні функцією Φ, а далі — у цільові розподіли оберненою функцією розподілу F⁻¹. |
| Чанк (chunk) | Незмінний за розміром *K* блок ітерацій Монте-Карло з власним потоком випадкових чисел; одиниця розподілу роботи між робочими процесами. |
